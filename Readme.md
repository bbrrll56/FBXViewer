# MR製品ビューワーシステム 仕様概要

## 概要
FBXファイルとパーツ情報（名前・説明文）を入力するだけで、  
Meta Quest上で動作するMR製品説明アプリを自動生成するシステム。

ユーザーはUnity Editorを操作する必要はない。

## システム構成

### 1. PC変換ツール
- FBX入力
- パーツ選択
- パーツ情報入力
- 自動変換（内部でUnity Editorをバッチ実行）
- Quest用パッケージ出力

### 2. Quest MRアプリ
- パッケージ読込
- 3Dモデル表示
- パーツ選択
- 説明表示
- 音声再生

## PCツール操作仕様

### パーツ選択
- 任意のパーツを1つ以上選択可能
- 複数パーツ同時選択対応

### 入力項目

#### 必須
- パーツ名（string）

#### 説明文
- string配列（1つ以上必須）
- 各要素が説明ステップとなる

例：
[
  "これはカバーです",
  "内部機構を保護します",
  "取り外し可能です"
]

## 音声生成仕様

- 説明文1要素につき音声1ファイル生成
- indexで1対1対応
- 出力形式は `.wav`

対応関係：
description[0] → audio[0]  
description[1] → audio[1]

## Questアプリ表示仕様

### 3D説明パネル
- 選択パーツに紐づいて表示

### 表示内容
- パーツ名：常時表示
- 説明文：index順で切り替え

### 音声再生
- `Play` ボタン押下時、現在選択中の説明文から最後の説明文まで連続再生
- 再生中は説明文表示も再生中の index に合わせて自動更新

### パーツ強調表示
- パーツ選択時には強調表示しない
- `Play` ボタン押下時のみ、対象パーツを約2秒フェード点滅
- 点滅は連続再生の最初の説明文に対してのみ実行
- 点滅中は対象パーツ以外を半透明表示
- 点滅終了後は対象パーツは通常色、その他パーツは半透明のまま維持

### パーツとFBXオブジェクトの対応付け
- PC変換ツールで選択したFBXオブジェクト名を、任意のパーツ名に bind して保存
- Viewer側は `partName` ではなく `selectedObjectNames` を使って実際のFBXメッシュを探索
- 1つのパーツに複数のFBXオブジェクトを紐づけ可能

## モデル仕様（FBX）

- ノード単位でパーツ分割されていること
- ノード名 = パーツID
- 重複禁止
- UV・法線正常

## 自動処理内容（PC側）

- FBXインポート
- マテリアル自動生成
- シェーダー統一
- ハイライト対応
- TextMeshProフォント生成（日本語対応）
- 音声生成
- AssetBundleビルド

## 出力構成

/Package  
  /Audio  
    *.wav  
  /Model  
    *.fbx  
  /Metadata  
    project_metadata.json  
  manifest.json  

## データ構造例

{
  "projectName": "NewProject",
  "parts": [
    {
      "partName": "砲塔",
      "descriptions": [
        "これは砲塔です。"
      ],
      "audioFiles": [
        "砲塔_0.wav"
      ],
      "selectedObjectNames": [
        "turret"
      ]
    }
  ]
}

## 特徴

- ノーコード運用
- FBX投入のみで利用可能
- 自動変換パイプライン
- Quest側は表示専用

## 制約

- FBXは命名規則に従う必要あり
- パーツは事前分割必須
- 完全自動認識は行わない

## 一言

FBX＋説明文を入れるだけで、MR上の製品説明アプリを自動生成するシステム
